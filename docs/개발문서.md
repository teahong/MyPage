# 나의 작업물 아카이브 개발 문서

## 1. 프로젝트 개요

### 1.1 목적
발표 자료, 앱, 웹사이트 등 개인 작업물을 한곳에 모아 기록하고 공개로 공유하는 아카이브 사이트를 만든다. 작업물은 계속 늘어난다. 관리자는 사이트 안에서 직접 추가, 수정, 삭제한다. JSON 파일 수정이나 GitHub 재업로드는 필요 없다.

### 1.2 사용자
| 구분 | 인원 | 권한 |
|---|---|---|
| 방문자 | 제한 없음 | 로그인 없이 목록, 검색, 필터, 상세 페이지 열람 |
| 관리자 | 1명 (본인) | Google 로그인 후 작업물과 카테고리 추가, 수정, 삭제 |

### 1.3 핵심 원칙
- 썸네일이 주인공이다. 카드에서 썸네일이 가장 크게 보인다.
- 읽기는 누구나, 쓰기는 관리자 이메일 1개만 가능하다.
- 접근 제한은 화면 숨김이 아니라 Firestore와 Storage Security Rules에서 이메일을 확인해 강제한다.
- Firebase 설정값은 공개되는 값이다. 코드에 들어가도 괜찮다. 보안은 Security Rules가 담당한다.
- 설정값은 `.env`로 관리하고 저장소에는 올리지 않는다.

### 1.4 사용 범위
- 실행 형태: 웹사이트. Vercel에 자동 배포 (GitHub 저장소 연동).
- 모바일 화면 최적화 포함. 기준 너비 360px 이상.
- 작업물 수는 수백 건 이하로 가정한다 (가정).

### 1.5 범위 밖
- 여러 관리자 지원
- 다국어 지원 (한국어만)
- 방문자 댓글, 좋아요 (가정: 제외)
- 다크 모드 (가정: 제외)
- JSON 백업 내려받기 (가정: 제외)
- 외부 검색 서비스 연동

## 2. 기술 스택

| 영역 | 기술 | 용도 |
|---|---|---|
| 프론트엔드 | React 18 + Vite | 화면 구성, 빌드 |
| 라우팅 | React Router | 목록, 상세 페이지 이동 (가정) |
| 데이터베이스 | Firebase Firestore | 작업물, 카테고리 저장 |
| 이미지 저장 | Firebase Storage | 썸네일 업로드 |
| 인증 | Firebase Authentication (Google) | 관리자 로그인 |
| 배포 | GitHub + Vercel | push 시 자동 배포 |
| 설정 | `.env` (Vite 환경변수) | Firebase 설정값, 관리자 이메일 |
| 글꼴 | Pretendard (CDN 또는 npm 패키지) | 전체 UI 글꼴 |
| 스타일 | 순수 CSS 파일 + CSS 변수 (가정) | 색상 토큰, 레이아웃 |

### 2.1 선택 이유
- React + Vite: 설정이 간단하고 Vercel이 바로 지원한다.
- Firebase: 서버 없이 DB, 파일 저장, 로그인을 한 번에 해결한다.
- 순수 CSS: 별도 UI 라이브러리의 기본 모양이 섞이는 것을 막는다 (가정).

### 2.2 구조 원칙
- Firebase 호출은 `src/services/` 폴더에만 둔다. 컴포넌트에서 Firebase를 직접 호출하지 않는다.
- 색상, 간격은 `src/styles/tokens.css`의 CSS 변수만 사용한다. 컴포넌트에 hex 값을 직접 쓰지 않는다.
- 환경변수 이름은 `VITE_` 접두사를 쓴다.
- 관리자 여부 판단은 `useAuth` 훅 한 곳에서 한다.

### 2.3 환경변수
`.env.example`을 저장소에 포함하고 실제 `.env`는 `.gitignore`에 넣는다.

```
VITE_FIREBASE_API_KEY=
VITE_FIREBASE_AUTH_DOMAIN=
VITE_FIREBASE_PROJECT_ID=
VITE_FIREBASE_STORAGE_BUCKET=
VITE_FIREBASE_MESSAGING_SENDER_ID=
VITE_FIREBASE_APP_ID=
VITE_ADMIN_EMAIL=
```

`VITE_ADMIN_EMAIL`은 화면의 관리자 버튼 표시용이다. 실제 권한은 Security Rules에 적힌 이메일로 결정된다.

## 3. 기능 요구사항

### 3.1 작업물 목록 보기
- 로그인 없이 누구나 열람한다.
- 정렬: 날짜 최신순 (날짜가 같으면 등록 시각 최신순).
- 카드 그리드 열 수: 데스크톱(1024px 이상) 3열, 태블릿(640~1023px) 2열, 모바일(639px 이하) 1열 (가정).
- 카드 구성: 썸네일(비율 16:10), 제목, 카테고리 라벨, 날짜.
- 카드 클릭 시 상세 페이지(`/work/:id`)로 이동한다. 실제 링크로 바로 이동하지 않는다.
- 무한 스크롤: 한 번에 12건씩 표시한다 (가정). 목록 끝에 도달하면 다음 12건을 보여준다. `IntersectionObserver`를 사용한다.
- 모든 건을 다 보여준 뒤에는 "마지막 작업물이에요" 문구를 한 줄 표시한다.
- 로딩 중: 캐릭터 이미지와 "불러오는 중" 문구를 표시한다.
- 작업물이 0건: 캐릭터 이미지와 빈 화면 문구를 표시한다. 관리자에게는 "추가" 버튼도 보인다.
- 불러오기 실패: "목록을 불러오지 못했어요. 다시 시도" 버튼을 표시한다.

### 3.2 카테고리 필터
- 목록 상단에 필터 버튼을 나열한다. 맨 앞은 "전체"이며 기본 선택 상태다.
- 기본 카테고리: 발표 자료, 앱, 웹사이트.
- 버튼 하나만 선택할 수 있다 (단일 선택).
- 선택된 버튼은 포인트 컬러로 채운다.
- 필터 변경 시 무한 스크롤 표시 개수를 12건으로 초기화한다.
- 모바일에서는 버튼 줄이 가로 스크롤된다. 줄바꿈하지 않는다.
- 해당 카테고리에 작업물이 없으면 빈 화면 문구를 표시한다.

### 3.3 카테고리 추가 (관리자)
- 작업물 등록/수정 폼의 카테고리 선택 항목에서 "새 카테고리 추가"를 선택하면 입력칸이 나타난다.
- 이름 규칙: 1~20자, 앞뒤 공백 제거, 기존 카테고리와 같은 이름(대소문자 무시) 불가.
- 저장하면 `categories` 컬렉션에 추가되고 필터 버튼에 즉시 반영된다.
- 기본 3개 카테고리는 삭제할 수 없다 (가정).
- 카테고리 이름 변경, 삭제 기능은 이번 버전에 넣지 않는다 (가정).

### 3.4 검색
- 헤더 아래 필터 위에 검색창 1개를 둔다.
- 방식: 앱 시작 시 모든 작업물의 `id`, 제목, 설명, 카테고리, 날짜, 썸네일 URL, 링크 URL을 한 번에 불러와 메모리에 보관한다 (가정). 화면에는 12건씩 나눠 보여준다.
- 검색 범위: 제목과 설명.
- 일치 방식: 부분 일치, 대소문자 무시, 앞뒤 공백 제거.
- 입력 후 300ms 뒤 결과를 갱신한다.
- 검색어와 카테고리 필터는 함께 적용된다 (AND 조건).
- 검색어를 지우면 전체 목록으로 돌아온다.
- 결과가 0건이면 "'검색어'와 일치하는 작업물이 없어요" 문구와 캐릭터를 표시한다.
- 작업물이 500건을 넘으면 방식 재검토가 필요하다 (가정). 문서에 한계로 명시한다.

### 3.5 상세 페이지
- 경로: `/work/:id`.
- 표시 항목: 큰 썸네일, 제목, 카테고리, 날짜, 설명 전체(줄바꿈 유지), "작업물 열기" 버튼, "목록으로" 링크.
- "작업물 열기" 버튼은 링크 URL을 새 탭에서 연다 (`target="_blank"`, `rel="noopener noreferrer"`).
- 존재하지 않는 id: "작업물을 찾을 수 없어요" 문구와 목록으로 가는 링크를 표시한다.
- 관리자에게는 "수정", "삭제" 버튼이 추가로 보인다.
- 페이지 제목(`document.title`)을 "작업물 제목 | 사이트 이름"으로 설정한다 (가정).

### 3.6 관리자 로그인
- 헤더 오른쪽 끝에 작은 "관리자 로그인" 텍스트 버튼을 둔다.
- 클릭하면 Google 로그인 팝업(`signInWithPopup`)이 열린다.
- 로그인한 이메일이 `VITE_ADMIN_EMAIL`과 같으면 관리자 모드가 된다. 헤더에 "추가" 버튼과 "로그아웃" 버튼이 나타난다.
- 다른 이메일이면 즉시 로그아웃시키고 "관리자 계정이 아니에요" 안내를 표시한다.
- 팝업을 닫거나 실패하면 "로그인하지 못했어요. 다시 시도해 주세요" 안내를 표시한다.
- 이메일 비교 시 대소문자를 무시한다.
- 로그인 상태는 새로고침해도 유지된다 (Firebase 기본 동작).

### 3.7 작업물 추가 (관리자)
진입: 헤더의 "추가" 버튼 → `/admin/new` 화면.

| 항목 | 필수 | 규칙 |
|---|---|---|
| 제목 | 필수 | 1~60자, 앞뒤 공백 제거 |
| 설명 | 필수 | 1~2000자, 줄바꿈 허용 |
| 카테고리 | 필수 | 기존 카테고리 중 선택 또는 새로 추가 |
| 링크 URL | 필수 | `https://` 또는 `http://`로 시작하는 올바른 URL |
| 썸네일 | 필수 | jpg, png, webp. 5MB 이하 |
| 날짜 | 필수 | 기본값 오늘. 날짜 선택기로 변경 가능 |

- 썸네일 선택 즉시 미리보기를 표시한다.
- 업로드 전 브라우저에서 긴 변 1600px 이하로 줄인다 (가정).
- 저장 순서: 썸네일을 Storage에 업로드 → 다운로드 URL 확보 → Firestore 문서 생성.
- Firestore 저장이 실패하면 방금 올린 썸네일 파일을 삭제한다.
- 저장 중에는 저장 버튼을 비활성화하고 "저장 중" 문구를 표시한다. 중복 클릭을 막는다.
- 저장 성공 시 해당 작업물의 상세 페이지로 이동한다.
- 필수 항목이 비어 있으면 해당 입력칸 아래에 빨간 안내 문구를 표시하고 저장하지 않는다.
- 비관리자가 `/admin/*` 경로로 들어오면 목록 페이지로 돌려보낸다.

### 3.8 작업물 수정 (관리자)
- 진입: 상세 페이지의 "수정" 버튼 → `/admin/edit/:id`.
- 입력 항목과 규칙은 추가와 같다. 기존 값이 미리 채워진다.
- 썸네일은 새 파일을 선택한 경우에만 교체한다. 선택하지 않으면 기존 썸네일을 유지한다.
- 교체 시 새 파일 업로드와 문서 갱신이 성공한 뒤 기존 파일을 삭제한다.
- 저장 성공 시 상세 페이지로 이동한다.

### 3.9 작업물 삭제 (관리자)
- 진입: 상세 페이지의 "삭제" 버튼.
- 확인 창에서 "정말 삭제할까요? 되돌릴 수 없어요." 문구와 "삭제", "취소" 버튼을 표시한다.
- 삭제 시 Firestore 문서와 Storage의 썸네일 파일을 함께 지운다.
- 삭제 성공 시 목록으로 이동한다.
- 썸네일 파일 삭제만 실패하면 문서 삭제는 유지하고 콘솔에 오류를 기록한다 (가정).

### 3.10 헤더
- 왼쪽: 캐릭터 이미지(높이 56px, 모바일 44px)와 인사말.
- 인사말 문구: "안녕하세요, 제 작업물을 모아뒀어요" (가정, 사용자 수정 가능).
- 오른쪽 끝: 관리자 로그인 또는 관리자 버튼.

## 4. 데이터 모델

### 4.1 Firestore

```
컬렉션: works
문서 ID: 자동 생성
  title          string     제목 (1~60자)
  description    string     설명 (1~2000자)
  category       string     카테고리 이름 (categories 컬렉션에 존재하는 값)
  linkUrl        string     실제 링크 (http/https)
  thumbnailUrl   string     Storage 다운로드 URL
  thumbnailPath  string     Storage 파일 경로 (삭제, 교체용)
  date           timestamp  사용자가 지정한 작업물 날짜
  createdAt      timestamp  문서 생성 시각 (serverTimestamp)
  updatedAt      timestamp  마지막 수정 시각 (serverTimestamp)

컬렉션: categories
문서 ID: 카테고리 이름 자체 (예: "앱")
  name           string     표시 이름 (1~20자)
  isDefault      boolean    기본 카테고리 여부
  createdAt      timestamp  생성 시각
```

- 정렬 쿼리: `works`를 `date` 내림차순, 같으면 `createdAt` 내림차순. 복합 인덱스가 필요할 수 있다. 콘솔 오류에 나오는 링크로 생성한다.
- 기본 카테고리 3개(발표 자료, 앱, 웹사이트)는 관리자가 처음 로그인했을 때 없으면 자동 생성한다 (가정).

### 4.2 Storage 경로

```
thumbnails/{작업물id 또는 uuid}-{timestamp}.{확장자}
```

### 4.3 Security Rules

Firestore (`firestore.rules`):

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function isAdmin() {
      return request.auth != null
        && request.auth.token.email == "관리자이메일@gmail.com"
        && request.auth.token.email_verified == true;
    }

    match /works/{id} {
      allow read: if true;
      allow create, update, delete: if isAdmin();
    }
    match /categories/{id} {
      allow read: if true;
      allow create, update, delete: if isAdmin();
    }
  }
}
```

Storage (`storage.rules`):

```
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    function isAdmin() {
      return request.auth != null
        && request.auth.token.email == "관리자이메일@gmail.com"
        && request.auth.token.email_verified == true;
    }

    match /thumbnails/{file} {
      allow read: if true;
      allow write: if isAdmin()
        && request.resource != null
        && request.resource.size < 5 * 1024 * 1024
        && request.resource.contentType.matches('image/(jpeg|png|webp)');
      allow delete: if isAdmin();
    }
  }
}
```

- `관리자이메일@gmail.com`은 실제 관리자 이메일로 바꿔 Firebase 콘솔에 붙여넣는다.
- 규칙 파일은 `firebase/` 폴더에도 보관한다. 배포는 콘솔에 직접 붙여넣는 방식을 안내한다.
- Firestore 규칙에 필드 검증(제목 길이 등)을 추가할지는 구현 단계에서 질문한다.

## 5. 화면 구성

| 화면 | 진입 경로 | 주요 내용 |
|---|---|---|
| 목록 | `/` | 헤더(캐릭터, 인사말), 검색창, 카테고리 필터, 카드 그리드, 무한 스크롤 |
| 상세 | `/work/:id` | 큰 썸네일, 제목, 카테고리, 날짜, 설명, 작업물 열기 버튼, 관리자용 수정/삭제 |
| 작업물 추가 | `/admin/new` | 입력 폼, 썸네일 미리보기, 새 카테고리 추가 |
| 작업물 수정 | `/admin/edit/:id` | 기존 값이 채워진 입력 폼 |
| 로딩 | 데이터 불러오는 동안 | 캐릭터 이미지, "불러오는 중" 문구 |
| 빈 화면 | 결과 0건 | 캐릭터 이미지, 안내 문구 |
| 없는 페이지 | 그 외 경로 | "페이지를 찾을 수 없어요", 목록으로 링크 |

### 5.1 디자인 가이드

**분위기**: 밝고 경쾌하다. 썸네일이 주인공이다. UI는 뒤로 물러난다.

**색상 토큰**

포인트 컬러는 캐릭터 이미지 파일을 확인한 뒤 확정한다. 아래 값은 임시 제안이다 (가정). 구현 전에 사용자에게 캐릭터 이미지 경로와 HEX 값을 질문한다.

| 이름 | hex | 용도 |
|---|---|---|
| `--color-bg` | `#FFFFFF` | 페이지 배경 |
| `--color-bg-soft` | `#F6F7F8` | 섹션 배경, 입력칸 배경 |
| `--color-text` | `#1B1D1F` | 본문, 제목 |
| `--color-text-sub` | `#6B7280` | 보조 문구, 날짜 |
| `--color-border` | `#E5E7EB` | 구분선, 입력칸 테두리 |
| `--color-accent` | `#FF7A45` (임시) | 선택된 필터 버튼, 링크, 주요 버튼 |
| `--color-accent-weak` | `#FFF1EA` (임시) | 포인트 컬러의 옅은 배경 |
| `--color-danger` | `#D92D20` | 삭제 버튼, 입력 오류 문구 |

- 포인트 컬러는 1개만 쓴다. 그 외 강조색을 추가하지 않는다.
- 글자색과 배경의 대비 비율은 4.5:1 이상으로 한다.

**글꼴**
- Pretendard, 대체 글꼴은 `system-ui, sans-serif`.
- 크기: 제목 28px, 카드 제목 18px, 본문 16px, 보조 문구 14px.
- 본문 행간 1.6.

**레이아웃**
- 최대 콘텐츠 너비 1120px, 가운데 정렬.
- 좌우 여백: 데스크톱 32px, 모바일 16px.
- 카드 간격 24px (모바일 16px).
- 섹션 간 위아래 여백 48px 이상.
- 카드 모서리 반경 16px. 썸네일 비율 16:10, `object-fit: cover`.
- 카드 호버: 위로 4px 이동, 150ms. 그림자는 호버 때만 약하게 나타난다. `prefers-reduced-motion` 설정 시 이동 효과를 끈다.
- 터치 대상 크기는 최소 44×44px.

**AI가 만든 티가 나는 기본값 금지 목록**
- 보라색, 파란색 그라데이션 배경이나 버튼
- 모든 요소에 같은 둥근 카드와 같은 그림자를 반복하는 구성
- 이모지를 아이콘으로 쓰는 것 (아이콘이 필요하면 SVG 아이콘 사용)
- 스크롤할 때마다 요소가 떠오르거나 페이드인되는 의미 없는 등장 애니메이션
- 유리 효과(blur) 배경, 네온 글로우
- 히어로 영역의 큰 그라데이션 문구
- 의미 없는 장식 도형, 점 패턴 배경
- "혁신적인", "손쉽게" 같은 마케팅 문구
- 정보 없이 반복되는 통계 카드

**UI 문구 원칙**
- 한국어 해요체. 한 문장 40자 이내.
- 버튼은 동사로 끝낸다 (예: "저장", "삭제", "작업물 열기").
- 오류 문구는 원인과 다음 행동을 함께 쓴다 (예: "5MB 이하 이미지만 올릴 수 있어요").
- 영어 에러 메시지를 그대로 노출하지 않는다.
- 캐릭터 말풍선 문구는 짧게 쓴다 (예: 빈 화면 "아직 등록된 작업물이 없어요").

**캐릭터 사용**
- 헤더: 높이 56px (모바일 44px).
- 로딩 화면, 빈 화면: 높이 160px, 가운데 정렬.
- 이미지 파일은 `src/assets/character.png`에 둔다. 투명 배경 PNG 또는 SVG를 권장한다 (가정).
- 대체 텍스트: "작업물 아카이브 캐릭터".

## 6. 보안·저장·백업

### 6.1 보안
- 읽기 공개, 쓰기는 관리자 이메일 1개만. Firestore와 Storage 규칙 모두 적용한다.
- 프론트엔드의 관리자 판단은 화면 표시용이다. 보안 근거로 쓰지 않는다.
- Firebase 콘솔 Authentication > Settings > 승인된 도메인에 Vercel 배포 도메인을 추가한다.
- 외부 링크는 `rel="noopener noreferrer"`를 붙인다.
- 사용자 입력은 React의 기본 이스케이프로 출력한다. `dangerouslySetInnerHTML`을 쓰지 않는다.
- 링크 URL은 `http:` 또는 `https:` 프로토콜만 허용한다 (`javascript:` 차단).
- `.env`는 `.gitignore`에 포함한다.
- Firebase 콘솔에서 Google Cloud의 API 키 제한(HTTP 리퍼러에 배포 도메인과 `localhost` 등록)을 권장한다 (가정).
- Firebase 예산 알림을 설정하도록 안내한다 (가정).

### 6.2 저장
- 작업물, 카테고리: Firestore.
- 썸네일: Storage (`thumbnails/`).
- 로그인 상태: Firebase Auth가 브라우저에 보관.

### 6.3 백업
- 자동 백업 없음. JSON 내려받기도 이번 버전에서 제외한다 (가정).
- 안내: Firebase 콘솔 > Firestore에서 데이터를 직접 확인할 수 있다. 정기 백업이 필요하면 다음 버전 후보로 둔다.

### 6.4 환경 설정 안내 (사용자가 직접 수행)

**Firebase 콘솔**
1. console.firebase.google.com에서 프로젝트를 만든다.
2. 프로젝트 설정 > 내 앱 > 웹 앱(`</>`)을 등록한다. 표시되는 설정값 6개를 복사한다.
3. Authentication > 시작하기 > 로그인 방법 > Google을 사용 설정한다.
4. Firestore Database > 데이터베이스 만들기 > 프로덕션 모드로 시작한다. 리전은 `asia-northeast3`(서울)을 권장한다.
5. Storage > 시작하기. 리전은 서울을 권장한다. Storage는 요금제(Blaze) 전환이 필요할 수 있다. 콘솔 안내를 확인한다.
6. Firestore > 규칙, Storage > 규칙 탭에 4.3의 규칙을 붙여넣고 게시한다.

**로컬**
1. 프로젝트 루트에 `.env` 파일을 만들고 설정값을 채운다.
2. `npm install` 후 `npm run dev`로 확인한다.

**GitHub와 Vercel**
1. GitHub에 새 저장소를 만들고 코드를 push한다. `.env`가 올라가지 않았는지 확인한다.
2. vercel.com에서 GitHub 계정으로 로그인하고 "Add New Project"로 저장소를 가져온다.
3. Framework Preset이 Vite인지 확인한다.
4. Environment Variables에 `.env`와 같은 7개 변수를 이름과 값 그대로 등록한다.
5. Deploy를 누른다.
6. 배포된 도메인(예: `xxx.vercel.app`)을 Firebase Authentication > Settings > 승인된 도메인에 추가한다.
7. 환경변수를 바꾼 뒤에는 Vercel에서 Redeploy를 해야 반영된다.

**SPA 라우팅**: `vercel.json`에 모든 경로를 `index.html`로 보내는 rewrite를 넣는다. 상세 페이지 주소로 직접 접속하거나 새로고침해도 404가 나지 않게 한다.

### 7.2 구현 순서
각 단계는 끝나면 실행해서 확인한다. 확인이 끝나기 전에 다음 단계로 넘어가지 않는다.

0. **계획 확인**: 이 폴더 구조와 구현 계획을 사용자에게 보여주고 승인을 받는다. 승인 전에는 코드를 작성하지 않는다. 캐릭터 이미지 경로와 포인트 컬러 HEX도 이때 받는다.
1. **프로젝트 생성**: Vite + React 프로젝트를 만들고 `npm run dev`를 실행한다. 확인: 브라우저 `localhost:5173`에 기본 화면이 뜬다.
2. **Firebase 콘솔 설정 안내**: 6.4의 Firebase 단계를 사용자가 수행한다. `.env`를 채운다. 확인: `.env`에 7개 값이 있다.
3. **디자인 토큰과 헤더**: `tokens.css`, Pretendard, 헤더(캐릭터, 인사말)를 만든다. 확인: 헤더에 캐릭터와 인사말이 보인다. 모바일 너비에서도 깨지지 않는다.
4. **Firebase 연결과 목록 읽기**: `firebase.js`, `worksService.js`로 Firestore 읽기를 구현한다. 임시로 콘솔에서 문서 1건을 수동 등록해 확인한다. 확인: 카드 1개가 화면에 나온다.
5. **로딩, 빈 화면**: 캐릭터를 쓴 로딩, 빈 화면을 만든다. 확인: 데이터 0건일 때 빈 화면이 나온다.
6. **관리자 로그인**: `useAuth`, 로그인/로그아웃 버튼, 이메일 검증을 만든다. 확인: 관리자 계정은 "추가" 버튼이 보이고, 다른 계정은 안내 문구와 함께 로그아웃된다.
7. **보안 규칙 적용**: 4.3의 규칙을 콘솔에 게시한다. 확인: 로그아웃 상태에서는 읽기만 되고, 쓰기를 시도하면 거부된다.
8. **작업물 추가**: `WorkForm`, 썸네일 업로드, 저장을 구현한다. 확인: 폼으로 등록하면 Firestore와 Storage에 데이터가 생기고 목록에 보인다. 썸네일이 없으면 저장이 막힌다.
9. **카테고리**: 필터 버튼, 새 카테고리 추가를 구현한다. 확인: 새 카테고리를 만들면 필터에 나타나고 클릭 시 해당 작업물만 보인다.
10. **상세 페이지**: `/work/:id`와 "작업물 열기" 버튼을 구현한다. 확인: 카드를 누르면 상세로 이동하고, 버튼이 새 탭에서 링크를 연다.
11. **수정과 삭제**: 수정 폼, 삭제 확인 창을 구현한다. 확인: 수정 내용이 반영되고, 삭제하면 Storage 파일도 사라진다.
12. **검색**: 전체 제목/설명을 불러와 부분 일치 검색을 구현한다. 확인: 검색어에 맞는 카드만 나오고, 필터와 함께 동작한다.
13. **무한 스크롤**: 12건씩 표시를 구현한다. 확인: 테스트 데이터 13건 이상에서 스크롤하면 다음 건이 나타난다.
14. **모바일 최적화**: 360px 너비에서 전체 화면을 점검한다. 확인: 가로 스크롤 없이 모든 기능이 쓰인다.
15. **GitHub와 Vercel 배포**: 6.4의 안내대로 진행한다. 확인: 배포 주소에서 목록이 보이고 관리자 로그인이 된다.
